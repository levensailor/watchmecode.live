Security

Isolation is a feature.

Candidate code and ATS data are sensitive. Here's how we keep each customer's workspace separate and its credentials sealed.

A schema per workspace

Each workspace (acme.{{ root_domain }}) stores its sessions, files, runs, recordings, and integrations in its own Postgres schema. Requests are routed by subdomain before any query runs.

Dedicated instances

Enterprise workspaces run on their own deployment and database, in the region you choose, with a custom domain if you want one.

Sign-in

Interviewers sign in with Google (OpenID Connect with PKCE). Sessions are bound to the workspace they were issued for, and hand-offs between our sign-in hub and workspaces use single-use Ed25519-signed tokens that expire in two minutes.

Candidates

Candidates don't need an account. Their access is a signed, time-limited token for one session.

Secrets

ATS API keys and webhook secrets are encrypted at rest (Fernet). Our API keys are stored only as SHA-256 hashes.

Webhooks and billing

Ashby and Stripe webhooks are verified with HMAC signatures, and Stripe events are processed once even when they're retried.

Code execution

Candidate code runs in short-lived sandboxes with time and output limits. Sandbox labs run in Firecracker microVMs.

Your data, your call

Admins can end sessions, export code as a zip, and request deletion. See the privacy policy.
